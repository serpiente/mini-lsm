crossbeam_skiplist::SkipMap vs std::collections::BTreeMap

Both are ordered key–value maps with O(log n) lookup. Everything else about them differs, and all of it follows from one choice: inline arrays versus per-entry allocations linked by atomic pointers.

Signatures — the observable difference

OperationBTreeMapSkipMap
insert fn insert(&mut self, K, V) -> Option<V> fn insert(&self, K, V) -> Entry<'_, K, V>
get fn get(&self, &Q) -> Option<&V> fn get(&self, &Q) -> Option<Entry<'_, K, V>>
remove fn remove(&mut self, &Q) -> Option<V> fn remove(&self, &Q) -> Option<Entry<'_, K, V>>
range fn range(&self, R) -> Range<'_, K, V> fn range(&self, R) -> Range<'_, Q, R, K, V>
get_mut fn get_mut(&mut self, &Q) -> Option<&mut V> does not exist — values are never mutated in place

Two things to notice. Every SkipMap method takes &self, including the mutating ones. And SkipMap never hands out a plain &V — always an Entry, which is a guard: it holds a reference count on the node so a concurrent remove cannot free the memory you are reading.

Layout — the cause of everything above

BTreeMap

B = 6, CAPACITY = 2B−1 = 11, MIN_LEN_AFTER_SPLIT = 5.

Each node holds keys: [MaybeUninit<K>; 11] and vals: [MaybeUninit<V>; 11] inline, plus len: u16 and a parent pointer. Internal nodes add edges: [BoxedNode; 12].

Insert into a full node splits it: the median key is promoted to the parent and about half the elements are copied into a fresh allocation. Elements relocate.

library/alloc/src/collections/btree/node.rs, l. 43–80

SkipMap

HEIGHT_BITS = 5, MAX_HEIGHT = 32.

One heap allocation per entry: #[repr(C)] struct Node { value, key, refs_and_height: AtomicUsize, tower }, where tower is a dynamically sized array of Atomic<Node> and must be the last field.

Insert allocates a node, stores its level-0 successor, then publishes it with one compare_exchange on the predecessor. Nothing relocates, ever.

crossbeam-skiplist-0.1.3/src/base.rs, l. 16–140

How a skiplist decides its shape

// base.rs :: random_height() — line 558
// Xorshift PRNG (Marsaglia), then:
let mut height = cmp::min(MAX_HEIGHT, num.trailing_zeros() as usize + 1);

// Then trim: don't build a tower far taller than anything already present.
while height >= 4 && self.head[height - 2].load(Relaxed, unprotected()).is_null() {
    height -= 1;
}

trailing_zeros() + 1 makes each additional level half as likely as the last — so p = ½, expected tower height 2, and P(height ≥ k) = 2−(k−1). Tall nodes are rare express lanes. search_bound starts at the highest occupied level and descends, skipping most of the list at each step.

This is the trade. A B-tree earns its balance by doing work on write (splitting, merging, rebalancing). A skiplist buys expected balance with randomness and does no rebalancing at all — which is exactly what makes a single-CAS insert possible.

Decision rule

If one thread owns the map, or a single RwLock around it is not a measured bottleneck: use BTreeMap. It is faster and smaller, and you keep worst-case guarantees.

Reach for SkipMap only when you need many threads reading and writing the same ordered map at once and the lock has been shown to hurt. You are paying cache locality and memory to delete a lock.

Two behaviours that will bite you

1. Overwrite is not mutation — it is replace

SkipMap::insert on an existing key does not update the value in place. It marks the old node dead and links a brand-new node:

// base.rs, l. 1095 — note the always-true replace predicate
pub fn insert(&self, key: K, value: V, guard: &Guard) -> RefEntry<'_, K, V> {
    self.insert_internal(key, || value, |_| true, guard)
}

Consequence: an Entry you obtained earlier keeps showing you the old value, and stays valid while doing so. That is a feature — it is a stable read snapshot of one key — but it surprises people who expect map semantics.

2. Removal is a two-phase, cooperative affair

mark_tower() sets the low tag bit on each of the node's pointers, from the top level down. A node is officially removed the instant its level-0 pointer is marked. Unlinking is then done opportunistically by whichever thread trips over it next:

// base.rs :: search_bound — every reader helps clean up
if succ.tag() == 1 {
    if let Some(c) = self.help_unlink(&pred[level], c, succ, guard) { … }
}

This is why readers must run inside an epoch guard (epoch::pin()): the memory is freed only once no thread can still be looking at it.
